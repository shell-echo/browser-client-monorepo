# 框架重建与依赖更新

[English](../reinit.md) · [中文文档](README.md) · [项目首页](../../README.zh-CN.md) · [开发](development.md) · [测试](testing.md) · [依赖安全](security.md)

reinit 更新框架基础、保留应用源码，并在替换前验证候选项目。先检查计划，再决定是否实际重建。根验证工具、部署文档和实例 `accessibilityPaths` 会保留，无障碍断言在浏览器替换门槛中执行，axe-core 参与根依赖兼容规划及离线重放。[可选资源保护](testing.md#可选资源保护)不改变断言或恢复权限，[部署与交付](deployment.md)说明生产 ZIP。

reinit 及子命令直接用 Node.js 24 执行 `.mts`，候选与最终 `pnpm check` 都包含严格工程类型检查。根 `tooling` catalog、编译器、类型和共享 TypeScript lint 依赖参与兼容更新。历史类型迁移基线来自本地严格 peer 验证的锁文件，并不声称查询过最新版本；成功在线 reinit 后会替换为正常求解记录，离线仍要求完整匹配的收据与缓存。

## 从官方模板重建

reinit 保留磁盘上的当前文件，包括未提交和未跟踪源码，不依赖 Git 提交或 `git restore`。导航、设置同步、侧栏偏好、共享界面、lint 范围及其回归测试都会保留，并在候选中再次验证。

```sh
pnpm reinit                   # 只显示计划，不联网、不写文件
pnpm reinit web --dry-run      # 预览指定目标
pnpm reinit --apply            # 重建所有注册应用
pnpm reinit admin --apply      # 更新后台及共享依赖，检查全部应用
pnpm reinit extension --apply
pnpm reinit --apply --offline  # 重放记录与缓存，不查询最新版本
```

执行前停止相关开发、构建服务并暂停编辑。实际流程：

1. 获取维护锁，核对源码内容、路径、类型和权限指纹。逐文件摘要防止内容伪装成相邻记录，从官方生成器 latest 通道解析稳定版本。
2. 在 `.reinit/staging/<id>` 隔离生成，固定实际生成器版本。Next.js 生成时关闭 agent 文件与反馈，既有应用 `AGENTS.md` 保留。`next dev` 仍可能更新官方托管说明，应自行复核。候选初始化本地 Git 边界以免父目录忽略规则隐藏源码，不创建提交或远端，原 Git 元数据保留；运行需要 Git。
3. 求解框架、CRXJS、共享依赖、Node 与 peer 约束，记录共享依赖回退原因，更新 catalogs 和清单，恢复应用源码并接回共享配置、组件、Tailwind 和 CRXJS，保留扩展 manifest。
4. 严格 peer 安装，核对实际解析版本，执行 `pnpm check` 和真实 Vite / CRXJS 兼容检查。在线还运行安全审计，并按候选 Playwright 版本准备 Chromium。即使只重建一个应用，`pnpm test:browser` 仍须覆盖全部注册实例。浏览器缺失、测试或清理失败均停止替换，输入快照与指纹检查拒绝并发编辑。
5. 将原应用、共享包、注册表、根清单、工作区配置、依赖目录、锁文件和版本记录移入 `.reinit/backups/<id>`，再安装候选目录。
6. 在最终位置严格冻结安装、运行检查并核对完整候选源码指纹。在线保留供应链元数据联网检查，离线只用缓存。失败且可安全恢复时还原原目录，保留冲突编辑、备份和失败候选供诊断。

| 内容                                                                              | 处理方式                                                                                                     |
| --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `src/`、`public/`、`.env*`、manifest、HTML、测试和业务文件                        | 从磁盘保留，整体替换模板示例目录                                                                             |
| `packages/` 源码、导出、脚本、peer 契约，根文档和 Git 元数据                      | 保留，不重建共享界面源码                                                                                     |
| 根与共享包直接依赖、catalogs                                                      | 在线更新为最高兼容稳定版本，保留其他字段与工作区设置                                                         |
| 应用 `package.json`                                                               | 保留非标准脚本、自定义字段和项目版本；更新显式托管依赖，其他应用依赖保持，框架依赖与标准脚本以官方模板为基础 |
| 应用 `tsconfig*.json`、框架/lint/PostCSS 配置、`next-env.d.ts`、`components.json` | 从新模板与适配器重建                                                                                         |
| 应用 `README.md`、`.gitignore`                                                    | 使用新模板，规范生成物与环境示例忽略规则；长期说明放根文档                                                   |
| 应用嵌套工作区清单与锁文件                                                        | 移除，统一使用根工作区和锁文件                                                                               |
| 仓库或工作区边界的依赖、构建和缓存                                                | 重建；业务目录内同名路径仍保留并计入指纹                                                                     |

Git 忽略规则锚定仓库和工作区边界，`public/dist/`、`src/dist/`、`src/cache.tsbuildinfo` 等业务路径仍可提交。真实 `.env*` 私有，脱敏示例可提交。`scripts/lib/gitignore.mts` 将该规则接回官方模板，同时保留上游其他排除项；回归调用真实 Git 验证。

需要长期保留的框架定制写入 `scripts/lib/integrate.mts`，不要只改生成配置。reinit 不自动迁移业务 API，上游结构或接口不兼容时在隔离阶段停止，先修适配器或源码再重试。生成器版本存于 `template-versions.json`，普通安装遵循锁文件。

扩展从官方 `create-vite --template react-ts` 生成，并要求最新稳定 Vite 与 CRXJS，精确版本写入清单和记录，每次在线重新查询。最新版本 peer 冲突时停止，不偷偷使用旧框架。该要求也适用于框架依赖经默认或命名 catalog 声明的情况；与未重建应用共用 catalog 不能削弱最新框架策略。普通共享依赖允许兼容回退。离线框架收据若记录了回退，或缺少对应最新稳定版本，应先在线重建；无依赖收据的旧记录仍走明确标记的旧版离线路径。

依赖记录跟随当前声明。移除的依赖、工作区和 catalog 条目会移除收据，在线移动声明位置会重建记录。部分重建保留未重建应用记录，并在锁定版本变化时刷新，以支持后续完整离线重放。离线可重用现有 catalog 收据，但新增托管位置缺记录时必须先在线处理；无效记录和旧 ESLint 9 收据会在替换前失败。

显式 `--offline` 不查询注册表、不下载浏览器、不执行在线安全审计。应先完成一次全部应用的在线重建以准备记录和缓存；生成器、依赖和匹配 Chromium 都要存在。可先执行 `pnpm exec playwright install chromium`，Linux 系统库按 Playwright 提示安装。旧版记录会标记 `legacy-offline`，仍执行 ESLint 最低版本、严格安装、浏览器验收、备份和恢复。在线失败不会自动转为旧版本重放。

浏览器报告、日志和截图保存在原项目 `.reinit/verification/`，候选替换后仍保留。独立测试可用 `BROWSER_TEST_OUTPUT_ROOT` 指定父目录，reinit 则显式使用原项目位置。共享主题事件隔离、移动侧栏重置与安全回归同样保留；在线或离线检查都会拒绝低于 10.7.4 的锁定或已安装 `ip-address`，不依赖在线审计是否可用。

每次实际 reinit 还生成私有 `.reinit/reports/reinit-<id>.json`，包含目标、在线/离线模式、超时、命令及依赖求解耗时、总时长、状态与保留锁信息。长阶段每 30 秒输出进度，不延长截止时间。预览不写任何报告。强制结束后恢复权威是备份 journal，不是诊断报告。

失败命令保留经过脱敏的 stdout 尾部：移除终端转义、常见凭据格式和已知敏感环境值，命令描述最多 1,024 字符、输出最多 4,096 字符。成功 JSON 不改写，超时、取消和不安全恢复错误保留原有语义。

## 依赖策略

`pnpm-workspace.yaml` catalogs 管理 React、React DOM、类型、Tailwind、Oxlint、ESLint、shadcn 和 Lucide；`catalog:next` / `catalog:vite` 管理框架工具链。后台和共享界面共用 Lucide 版本，应用声明框架、插件与 CRXJS。在线更新根工具与共享包直接依赖，但保留组件源码、导出、脚本和 peer 契约。

普通安装严格遵循锁文件。在线重建从发布者 latest 通道选择稳定版本，排除 beta / rc，不跟随 next。Next.js、Vite、CRXJS 必须最新稳定；共享依赖按 Node、模板与 peer 约束选择最高兼容稳定版本，并记录回退原因。React 与 React DOM 必须一致，Node 类型跟随当前 Node 主版本，TypeScript 保留模板约束，未重建应用的工具链继续构成约束。

新的废弃版本会被拒绝；若兼容性要求保留当前已使用的废弃版本，会在收据中记录。结果位于 `template-versions.json#dependencies`，随后执行严格安装、锁图核对、完整检查与在线审计，不能将缓存当作在线最新版本。

项目使用 ESLint 10，网站保留官方 Next.js Core Web Vitals / TypeScript 规则。模板默认不是硬约束，兼容性由真实配置 peer、严格安装和规则测试决定。当前 React 插件 7.37.5、Import 2.32.0、JSX a11y 6.10.2 的精确 `peerDependencyRules.allowedVersions` 例外用于其未声明的 ESLint 10 peer 范围，其他 peer 仍严格。回归实际执行 React、Hooks、a11y、Import、Next 和 TypeScript 规则；以后升级不能自动扩大例外。

ESLint 最低为 `10.0.0`，共享配置 peer 为 `^10`。在线求解、离线收据、旧锁文件和实际安装图都执行此下限，缓存 ESLint 9 也拒绝。缺少可核对版本或低于下限时先在线重建，找不到兼容组合就保留原项目。

应用专属依赖默认保持锁定，除非被起始项目显式托管。后台 `react-router` 在所有在线重建中参与更新，即使目标是其他客户端；集成范围 `^8.0.0`，再受 Node 与 peer 约束。支持新主版本需要明确适配与浏览器验证。原路由器基线记录不声称新查注册表，离线收据缺失或不兼容时停止。

共享界面依赖参与兼容升级，但不重生成已有组件。Node / pnpm、应用源码和业务 API 不自动迁移。策略位于 `scripts/lib/updates.mts`，catalog 适配位于 `scripts/lib/catalogs.mts`。

## 失败恢复与备份

生成或候选检查失败不触碰原目录；最终位置验证失败时恢复。Ctrl-C / SIGTERM 取消当前命令及其拥有的进程树，等待退出，必要时强制终止。如果不能确认退出，保留锁和现场，不自动恢复以避免并发写入。

macOS 回收进程组时，信号可能短暂返回 EPERM。清理继续有界检查，必须实际观察到 ESRCH；持续权限失败或进程组仍运行时保留归属证据，不允许据此还原或删锁。

普通命令默认十分钟，完整浏览器套件单独默认二十分钟，含复制、离线安装、构建、断言和清理，不是整个 reinit 的总期限。`REINIT_COMMAND_TIMEOUT_MS` 同时覆盖二者；`REINIT_BROWSER_TIMEOUT_MS` 仅覆盖浏览器且优先。二者接受正整数毫秒，零不能禁用。无效值在获取锁前失败。例：`REINIT_BROWSER_TIMEOUT_MS=1800000 pnpm reinit --apply` 将浏览器上限设为三十分钟，普通命令仍十分钟。浏览器内部安装、构建仍有自己的较短期限；超时不会自动重试或跳过验证。

嵌套 runner 将分离进程登记在系统临时目录的私有归属树中，并使用命令实际环境。每个命令有独立分支，停止一个不影响兄弟服务；正常结束、超时与取消都要核对嵌套进程退出，不能只看中间父进程退出。维护或恢复主进程被 SIGKILL 后，存活子进程仍阻止后续恢复。在登记中断、记录不可读或退出不确定时保留恢复状态；恢复未解决前保留归属分支，成功恢复只释放自己的记录，不丢弃其他恢复证据。

注册表和下载默认 120 秒、最多两次重试、间隔 1–5 秒，安装网络并发默认 4；pnpm 11 的 `pnpm_config_fetch_timeout` / `pnpm_config_fetch_retries` 可覆盖。`.reinit` 被 Git 忽略，可能含环境文件，是私有本地备份，不是异地备份或断电原子事务。

pnpm 可能针对显式新版本添加精确 `minimumReleaseAgeExclude`，包含平台包，例外随配置一起备份和回滚，不全局关闭发布时间保护；临时生成器例外不带入项目。

强制结束或断电后，先检查 `.reinit/lock/owner.json`、备份 `journal.json` 和原目录、备份、候选的实际位置，**不要直接删锁或备份**。正常失败会释放锁，但不自动删除备份。

使用 `pnpm app recover OPERATION_ID` 检查，只有确认原主进程和记录的子进程组退出后才加 `--apply`。根清单或依赖暂缺时用 `node scripts/app.mts recover OPERATION_ID --apply`。恢复根据预写计划核对文件系统，可在再次中断后续跑；冲突和归属不明保留锁。移除归档 `.reinit/archives/` 不参与普通清理。

恢复会原子认领一个 owner 代次，防止并发恢复同时修改。每次恢复登记新代次；新 owner 记录写完前中断的认领仍受保护，需要人工检查。

人工恢复时先停止相关进程，把当前 `apps/`、`packages/`、注册表、根清单、工作区配置、依赖、锁文件和版本记录移到新保留目录，再按同一备份 `journal.json#paths` 恢复匹配路径，随后冻结安装并运行完整检查。旧备份可能缺根清单，必须跟随其 journal，不混用不同快照的锁文件与源码。

## 清理旧的成功工作区

```sh
pnpm reinit:clean                        # 预览，默认每类保留最近三份及最近七天
pnpm reinit:clean --sizes                # 额外扫描总量、可清理与保留数据的逻辑大小
pnpm reinit:clean --keep=1 --days=0       # 预览更小的保留窗口
pnpm reinit:clean --keep=1 --days=0 --apply
```

只有同时超过数量与天数限制的成功备份及其暂存目录可清理。浏览器清理支持平铺与 `<run>/<instance>/workspace` / `profile-*` 布局；多实例父报告和每份实例报告必须在成功状态、身份、本地输出位置和源码指纹上匹配。报告缺失、畸形、变化或失败时保护整套目录，未列目录保持不动，有维护锁也保护。删除前重新核对报告摘要，只清理合格副本和浏览器配置，保留报告、日志和截图。

失败或不完整恢复记录、无有效记录的目录和迁移基线受保护。清理拒绝已有维护锁，并获取同一把锁；每类至少保留一份近期成功记录，拒绝符号链接。Ctrl-C / SIGTERM 完成本次删除后停止后续删除并释放锁，已删除副本不能恢复；SIGKILL 或断电后需人工检查锁。

真实重建与组合验收可能生成多层副本，运行前为磁盘留足余量，并在完成后检查保留窗口。`--sizes` 只额外统计，不改变可清理范围；符号链接不跟随目标，硬链接与共享块可能使逻辑大小大于实际可回收空间。放弃失败现场或迁移快照恢复能力属于额外人工决策，不是这个命令默认提供的行为。

## 扩展通信的保留

共享 SDK、manifest、侧边栏入口、来源策略和浏览器断言都由 reinit 保留；新实例从独立种子接入同样的机制。来源白名单不自动扩大，生产入口和真实浏览器门槛继续执行。[扩展通信指南](extension-communication.md)。
